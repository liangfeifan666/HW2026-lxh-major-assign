# OmniInfantry 全向轮步兵双板工程

本工程基于队内 `omni_skeleton`，包含底盘板 `Chassis` 与云台板 `Gimbal`，共享协议位于 `RobotComponents`。实现目标是完成考核说明中的双板通信、麦轮逆解、三模式、云台两轴位置环、IMU、状态机、遥控接收和 IWDG 保护。

> 当前两板 Debug 固件已编译链接成功，但尚未进行实车验证。PID、方向、限位和 CAN 接线必须按本文完成上机前检查后，才能从低幅度、车轮离地的单步测试开始。

## 0. 当前状态（2026-10-28）

暂停点及后续审查发现的问题已处理，包括：PID 首拍与角度回绕微分、CAN 启动/bus-off/旧邮箱、DM 严格零转矩与受控恢复、IMU 读取错误/新鲜度/实际采样间隔、DBUS 帧校验、双板重锁和共享组件重复维护。两板已重新 Configure 并构建链接成功。

**仍未烧录、未做实车验证。** 编译与静态审查不能证明方向、PID、机械限位和总线时序正确；必须继续完成第 6、7 节的离地与故障注入测试，不能直接落地跑车。

## 1. 已实现内容

- `RobotComponents`：生命状态、底盘/云台模式、运动结构、8 字节定点双板协议、100 ms 离线判断，以及两板统一的 `pid_controller`、`imu_controller`、`can_lifecycle` 实现。
- `Chassis`：四轮 M3508 实例与反馈离线检测、速度 PID、麦轮逆解、云台系到底盘系旋转、分离/跟随/小陀螺、三态状态机。
- `Gimbal`：两台 DM-J4310 力矩接口、反馈离线检测、yaw/pitch 位置 PID、yaw 最短角误差、pitch 软件限位、遥控解锁与三态状态机。
- `Task`：1 ms TIM6 调度、CAN 启动与分发、USART3 空闲+DMA 接收、持续发送安全帧、条件喂狗。
- `Imu`：BMI088 初始化、500 个静止样本的非阻塞零偏估计、1 kHz Mahony 姿态更新。

## 2. 遥控档位与输入约定

遥控器数据只由云台板直接读取。云台板通过 G2C 帧把底盘指令和 `remote_working` 发给底盘板；底盘没有有效双板帧或该标志为假时，四轮始终输出零。

| 输入 | 功能 |
| --- | --- |
| 右拨杆下 | 急停/锁定；两板均输出零 |
| 右拨杆中 | 分离模式 |
| 右拨杆上 + 左拨杆中 | 跟随模式 |
| 右拨杆上 + 左拨杆上 | 小陀螺模式 |
| 左拨杆下 | 保留，不允许进入工作状态 |
| 左摇杆纵/横 | 云台系 `vx/vy`，最大各 1.2 m/s |
| 右摇杆横/纵 | yaw/pitch 目标角速率，最大 1.5/0.8 rad/s |
| 拨轮 | 分离模式直接映射 `w`；小陀螺模式偏转后进入 0.8～5 rad/s 限速自旋；跟随模式忽略 |

上电后必须先收到有效右拨杆下档，再切到允许档位，且五路输入回中保持 300 ms，才会进入 `Working`。遥控断线或运行中发生关键故障后，需要重新经过锁定档。小陀螺没有隐藏固定转速，拨轮回中即 `w=0`。

## 3. 安全链路

1. 默认 `Dead`，电机输入全部显式设为零。
2. 进入工作态要求：有效解锁、完整 18 字节 DBUS 且未离线、IMU 零偏完成、本板关键电机反馈在线且 DM 已使能、双板通信在线。
3. 底盘还要求云台板处于 `Working` 且 `remote_working=true`。
4. 急停、遥控/电机/双板离线、IMU 异常、非法档位或异常浮点输入均回到安全路径。
5. 安全路径不是“停止发报文”：每周期继续发送零电流/零转矩与双板心跳，避免执行器保持最后一条非零指令。
6. 底盘三个目标速度同时为零时直接零输出并清 PID，不对残余轮速施加制动电流。
7. 输入、跟随角速度、轮速、M3508 原始输出、DM 力矩和 pitch 目标均有限幅；轮速超限采用等比缩放。
8. 只有 `Robot::update()` 完整结束且主循环后台心跳未超过 100 ms 时才喂 IWDG；后台或控制路径卡死都会停止喂狗。调试器 halt 时冻结 IWDG，不影响正常运行保护。
9. CAN 发送失败会中止旧邮箱并重试，电机 CAN 的发送/总线健康直接参与 `hardwareReady()`；bus-off 由硬件 ABOM 恢复，恢复期间禁止输出。
10. DM 正常编码和异常兜底均使用精确零转矩；运行故障不会自动重新武装，只有操作手重新经过锁定档后才在零转矩下清错/使能。
11. IMU 读取失败、数据超过 100 ms 未更新或后台采样停滞均禁止工作；姿态与采样时间戳以短临界区一致发布，Mahony 使用实际采样间隔。

## 4. 通信与实车参数

### CAN 分配

- CAN1：电机控制与反馈。
- CAN2：双板通信。
- C2G：`0x210`；G2C：`0x211`，均为 8 字节标准数据帧。
- 四轮顺序：LF、LB、RB、RF；M3508 ID：1、2、3、4，共用控制帧 `0x200`。
- DM-J4310：yaw ID=1、反馈 `0x11`；pitch ID=2、反馈 `0x12`。

### 已按补全任务书配置

- 四轮均反向，轮半径 `0.07786 m`，半轮距与半轴距均为 `0.15338 m`。
- yaw 正向、偏移 `-1.36920 rad`；pitch 反向、偏移 `0.02480 rad`。
- 平移指令始终定义在云台系，使用 `δ=云台相对底盘 yaw 关节角` 旋转到底盘系。
- pitch 初始软限位为 `[-0.30, +0.30] rad`，这是保守调试值，不代替机械限位实测。

## 5. 构建

在仓库根目录执行：

```bash
cmake --preset Debug -S Chassis
cmake --build Chassis/build/Debug --parallel

cmake --preset Debug -S Gimbal
cmake --build Gimbal/build/Debug --parallel
```

ELF 分别输出到 `Chassis/build/omni_chassis.elf` 和 `Gimbal/build/omni_gimbal.elf`，供现有 Ozone 工程使用。新增源文件后必须重新执行 Configure。当前链接器会报告骨架原有的 `LOAD segment with RWX permissions` 警告，未修改 CubeMX 链接脚本。

## 7. 安全验收顺序

1. 上电时拨杆直接放在工作档：不得输出；切到下档再解锁后才行。
2. 未接遥控器、拔出 DBUS、右拨杆急停：两板持续收到零指令。
3. 分别断开一台电机反馈和双板 CAN：对应系统回到 `Dead`，不得沿用旧反馈继续动。
4. 分离模式摇杆和拨轮全部回中：四轮原始指令必须为零。
5. 小陀螺只由拨轮调速，回中停转；退出档位立即停转。
6. 跟随模式验证车头向云台方向收敛；若反向，先断电核查角度/方向符号，禁止盲目加大 PID。
7. 验证 yaw 过 `±π` 不走长弧，pitch 到软限位后只能向允许区间运动。
8. 分别制造 CAN bus-off、控制循环卡死和主循环后台卡死：故障时输出归零，看门狗按预期复位；总线恢复后必须重新解锁才能输出。
9. 模拟 DM 失能/故障和首次使能帧丢失：不得在 `Dead` 中自动反复武装；重新锁定后才能在零转矩下恢复。
10. 暂停 IMU 后台采样超过 100 ms：不得继续沿用旧姿态工作，且后台心跳超时后应停止喂狗。

## 8. 组件边界说明

- 云台位置环使用角度增量计算阻尼，不依赖 DM 速度反馈；组件原有的速度位解包问题也已修正，便于后续诊断或速度环扩展。
- `CAN_Send_Msg()` 返回 `HAL_StatusTypeDef`；失败时先中止旧邮箱，确认有空邮箱后重试。电机 CAN 的发送结果与 BOFF 状态会传入顶层安全门控。
- 原始骨架中的 `.jdebug`、`.mxproject` 已被首次提交跟踪；`.gitignore` 只能阻止之后的新文件，不会自动取消既有文件的跟踪。
